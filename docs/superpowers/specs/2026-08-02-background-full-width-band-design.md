# 배경 요소 "가로 100%" (전체 폭 밴드) — 설계

작성 `2026-08-02`. 대상: 배경 편집기(페이지1 = 월 선택, 페이지2 = 요일 보드).

## 문제

배경 요소(`elements[]`)의 `x/y/w`는 **`.page-bg-el-frame`** 기준 %다. 이 프레임은
`positionBgElFrame()`이 활성 화면의 `.section-inner`(콘텐츠 열)를 실측해 만든 박스라,
`w:100`은 "화면 가로 100%"가 아니라 "콘텐츠 열 폭 100%"를 뜻한다. 따라서 하단 footer
영역에 화면 끝에서 끝까지 깔리는 배경 패턴을 만들 수 없고, 폭을 눈대중으로 키워도
디바이스가 바뀌면 어긋난다.

## 해결 방향

전체 배경(`.page-bg-full`)·영상·틴트는 이미 **`#pageBgLayer`**(= `.app-shell`,
뷰포트 가로 전체 · 헤더~footer 바닥) 기준으로 그려진다. 두 좌표계가 이미 공존하므로,
새 개념 없이 **"이 요소만 레이어 기준으로 렌더한다"는 요소별 플래그**를 추가한다.

## 데이터 모델

`page_backgrounds.data.elements[]` 항목에 **선택 필드 5개 추가**. jsonb 내부라
**마이그레이션 불필요**. 필드가 없는 기존 요소는 현행 경로로 동일하게 렌더된다.

| 필드     | 값                      | 기본값      | 의미                                       |
| -------- | ----------------------- | ----------- | ------------------------------------------ |
| `fw`     | `true`                  | 없음(=off)  | 가로 100% 밴드 모드                        |
| `fmode`  | `"stretch"` \| `"tile"` | `"stretch"` | 늘리기 / 가로 반복                         |
| `anchor` | `"bottom"` \| `"top"`   | `"bottom"`  | 세로 기준 가장자리                         |
| `off`    | px (숫자)               | `0`         | 그 가장자리 ↔ 밴드 끝단 거리. **0 = 밀착** |
| `th`     | px (숫자)               | `120`       | tile 모드 밴드 높이 (= 패턴 배율)          |

- `x / y / w / r`은 밴드 모드에서 **무시하되 값은 보존** → 체크 해제 시 원래 자리·크기로 복귀.
- `off`가 %가 아니라 **px**인 것이 핵심이다. 페이지 전체 높이는 디바이스마다 크게 달라
  %는 흔들리지만, px는 "어느 기기에서도 바닥에서 정확히 N px"가 보장된다.
- `fx`(좌우반전)는 두 모드 모두 유지. **`r`(회전)은 밴드에서 적용하지 않는다** — 회전한
  띠는 좌우 끝에 삼각형 빈틈이 생겨 "가로 100%"가 깨진다.

## 렌더 (`app.js applyPageBackground`)

밴드는 프레임이 아니라 **레이어 직속**으로 붙인다.

- **stretch** → `<img class="page-bg-el page-bg-band">`, `left:0; width:100%; height:auto`
  - `bottom|top: {off}px`. 비율 유지 확대. 로드 실패 시 self-remove(기존과 동일).
- **tile** → `<div class="page-bg-el page-bg-band page-bg-band--tile">`,
  `height:{th}px` + `background-repeat:repeat-x; background-size:auto 100%`.
  밴드 높이가 곧 패턴 배율이고, 높이는 디바이스와 무관하게 일정하다.

### 쌓임 순서 (기존 동작 보존이 걸린 지점)

밴드는 프레임 **밖**이라 DOM 순서만으로는 일반 요소와 앞뒤를 정할 수 없다. →
**모든 요소에 `z-index: 배열index + 1`을 명시**해 기존 `[앞으로]/[뒤로]`가 밴드/일반
요소 사이에서도 그대로 동작하게 한다. `.page-bg-el-frame`은 `z-index:auto`라 쌓임
맥락을 만들지 않으므로 프레임 안 요소의 z-index도 레이어 맥락에서 함께 경쟁한다.

⚠ **부작용과 보정**: `.page-bg-layer.has-full::after`(상단 382px 스크림)는 의사요소라
레이어의 **마지막 자식**으로 취급된다. 지금은 요소와 스크림이 모두 `z-index:auto`라
트리 순서대로 칠해져 **스크림이 요소 위에** 온다. 요소에만 양수 z-index를 주면 요소가
스크림 위로 튀어나와 기존 페이지의 겉모습이 바뀐다. → **스크림에 `z-index:1000`을 부여**
해 지금처럼 맨 위에 남긴다.

`main`/`.site-footer`는 `z-index:2`이고 레이어는 `z-index:1`(쌓임 맥락)이므로, 레이어
내부에서 z를 아무리 올려도 **밴드가 페이지 내용이나 footer 글자를 덮는 일은 구조적으로
불가능**하다.

## 편집기 (`background-editor.js` + `index.html`)

`[선택한 요소]` 패널에 추가:

```
☑ 가로 100% (페이지 전체 폭)
   채우기     ◉ 늘리기   ○ 가로 반복
   세로 기준  ◉ 아래     ○ 위
```

- **체크 시 자동 초기값**: 현재 렌더 위치에서 계산 — 가까운 가장자리를 `anchor`로,
  그 거리를 `off`(음수는 0)로, 현재 높이를 `th`로. 켜자마자 있던 자리 근처에서 폭만 넓어진다.
- **드래그**: 세로만 이동(= `off` 조정). `anchor:"bottom"`이면 위로 끌수록 `off` 증가.
- **핸들**: stretch는 크기·회전 핸들 없음(폭이 잠김). tile은 **자유로운 쪽 가장자리**
  (bottom 앵커 → 위쪽 / top 앵커 → 아래쪽) 중앙에 높이 핸들 하나, 배지에 px 표시.
- **키보드**: ↑/↓ = 1px, Shift = 10px (앵커 방향에 맞춰 화면상 위/아래로 이동).
  ←/→는 밴드에서 무시.
- 편집 캔버스도 동일 지오메트리로 렌더 — WYSIWYG 유지.

## 검증

Playwright 시드 배경으로 **320 / 768 / 1024 / 1366 / 1920** 실측:

1. 밴드 폭 == 레이어 폭(= 뷰포트 폭), 모든 폭에서.
2. `anchor:"bottom", off:0` → 밴드 바닥 == 레이어 바닥(±1px).
3. tile 밴드 높이가 뷰포트 폭과 무관하게 `th`로 일정.
4. stretch 밴드는 원본 비율 유지(높이 = 폭 × 원본비).
5. `anchor:"top"` 동작.
6. **기존 non-fw 요소 회귀**: 프레임 기준 좌표 불변, 스크림이 여전히 요소 위.
7. `npm.cmd run qa`.
