# 페이지 배경 편집기 — 디자인 스펙

날짜: 2026-07-21 · 상태: 사용자 승인 완료 (구현 전)

## 목적

관리자가 각 레벨의 페이지1(월그리드)·페이지2(요일그리드)의 body+footer 배경을
코드 수정 없이 직접 꾸밀 수 있게 한다. 헤더 영역은 제외한다.

## 확정된 요구사항 (질의응답 결과)

| 항목        | 결정                                                        |
| ----------- | ----------------------------------------------------------- |
| 편집 위치   | 실제 페이지 위에서 WYSIWYG 편집 (관리자 로그인 시)           |
| 모드 관계   | 전체 배경이미지 + 투명 PNG 요소 다수 배치, 동시 사용 가능    |
| 요소 조작   | 위치 드래그, 크기 조절(비율 유지), 좌우 반전, 회전           |
| 일괄적용    | 레벨 기본값 + 월별 덮어쓰기 (기본값 수정 시 자동 반영)       |
| 반응형      | 위치·크기를 % 저장, 모든 기기에서 비율 유지 자동 스케일      |
| 이미지 관리 | 공용 라이브러리 (한 번 업로드 → 모든 페이지에서 재사용)      |
| 저장 구조   | 전용 테이블 `page_backgrounds` + 전용 버킷 `backgrounds`     |

## 1. 배경 표시 (모든 방문자)

- 페이지1(`#monthScreen`)·페이지2(`#contentScreen`)의 body+footer 영역 뒤에
  배경 레이어를 삽입한다. 헤더는 제외.
- 레이어는 `pointer-events: none` — 기존 버튼/그리드 동작에 영향 없음.
- 레이어 구성 (아래→위): 전체 배경이미지 1장(cover, 여백 없이 꽉 채움,
  비율이 다르면 가장자리 잘림) → 투명 PNG 요소들(z 순서대로).
- 전체 배경이 없으면 기존 레벨 테마색(`level-theme-N`)이 그대로 보인다.
  설정하지 않은 페이지는 현재와 100% 동일.
- 페이지2 해석 규칙: 해당 (레벨, 월) 행이 있으면 그 행을 통째로 사용,
  없으면 (레벨, 기본값) 행 사용. 병합하지 않는다.
- 로딩: 기존 `contentCache` 패턴과 동일 — 캐시 즉시 적용 후 Supabase
  hydrate로 갱신.

## 2. 편집 모드 (관리자 전용)

- 관리자 로그인 상태에서 페이지1/페이지2 진입 시 우하단에
  "배경 편집" 플로팅 버튼 표시.
- 편집 모드 진입 시:
  - 오른쪽 라이브러리 패널: 업로드된 이미지 썸네일 목록, 새 이미지 업로드
    (클릭/드래그앤드롭), 전체 배경이미지 지정 슬롯, 라이브러리 이미지 삭제.
  - 썸네일 클릭 → 요소가 화면 중앙에 추가됨.
  - 요소 선택 시: 드래그 이동, 모서리 핸들 크기 조절(비율 유지),
    회전 핸들, 좌우반전/앞으로/뒤로/삭제 버튼.
  - 페이지 콘텐츠는 그대로 보이며 그 위에서 편집 (보이는 그대로 저장).
- 저장 버튼:
  - 페이지2: [이 월에만 저장] / [레벨 기본값으로 저장] /
    [이 월 개별설정 삭제(기본값으로 되돌림)]
  - 페이지1: [저장] (레벨당 1개 설정)
- 미저장 상태로 페이지/월 이동 시 경고.
- `#admin` 콘텐츠 탭에 "배경 편집" 바로가기 추가 — 선택된 레벨/월 페이지로
  이동하며 편집 모드 자동 진입 (관리자모드-사용자화면 일치 원칙).

## 3. 데이터 저장 (Supabase)

### 테이블 `page_backgrounds`

- 컬럼: `id`, `level`(text), `page`(text: `page1`|`page2`),
  `month`(text, `''` = 레벨 기본값), `data`(jsonb), `updated_at`
- 기본키: (level, page, month) — month는 '' 기본값의 not null 컬럼 (Supabase upsert onConflict 호환)
- `data` 스키마:

```json
{
  "full": "https://.../backgrounds/xxx.jpg 또는 null",
  "elements": [
    { "src": "URL", "x": 50, "y": 30, "w": 18, "r": 0, "fx": false, "z": 1 }
  ]
}
```

- `x`,`y`: 요소 중심의 레이어 대비 % 위치. `w`: 레이어 너비 대비 % 너비
  (높이는 원본 비율로 자동). `r`: 회전 deg. `fx`: 좌우반전. `z`: 쌓임 순서.
- RLS: 읽기 공개, 쓰기 관리자만 (`content_pages`와 동일 패턴).

### Storage 버킷 `backgrounds`

- 공개 읽기, 업로드/삭제는 관리자만.
- 라이브러리 목록 = 버킷 파일 목록 (별도 테이블 없음).
- 허용 형식: PNG/JPG/WebP, 파일당 5MB 제한.
- 테이블·버킷 생성 SQL은 파일로 준비하며, Supabase 대시보드에서 1회 실행.

## 4. 반응형

- % 기반 저장으로 모든 기기에서 자동 스케일 (작업은 PC에서 1회).
- 편집 UI는 PC 최적화, 표시(뷰어)는 전 기기 지원.
- 좁은 화면에서 요소-콘텐츠 겹침이 생길 수 있으나 요소는 항상 콘텐츠 뒤라
  조작에 지장 없음 (승인된 트레이드오프).

## 5. 예외처리

- 요소 이미지 로드 실패 → 해당 요소만 숨김, 페이지 정상 동작.
- Supabase 연결 실패 → 배경 없이 기존 테마색 폴백 (현재와 동일).
- 라이브러리 이미지 삭제 시 "사용 중인 페이지가 있을 수 있음" 경고 표시.

## 6. 완료 기준

- `npm.cmd run qa` (기존 Playwright 스위트) 통과.
- 수동 확인: 4레벨 × (페이지1 저장/표시, 페이지2 기본값 저장 → 10개 월 반영,
  특정 월 오버라이드 → 해당 월만 변경, 오버라이드 삭제 → 기본값 복귀).
- 비관리자/비로그인 방문자에게 편집 버튼이 보이지 않음.
- 배경 설정이 없는 페이지는 기존과 픽셀 단위 동일.

## 범위 제외

- 메인(홈) 페이지 배경 — 이번 범위 아님.
- 기기 유형별 개별 배치, 요소 투명도 조절 — 질의에서 제외로 확정.
- V2/V3 콘텐츠 화면 — 미사용/보관 상태라 제외.
