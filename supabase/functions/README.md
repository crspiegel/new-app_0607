# Edge Function 배포 절차 — `teacher-resource-download` (교사 자료실 다운로드)

교사 자료실 파일을 내려받는 **유일한 길**이다. 브라우저가 `{level, slot}`만 보내면 이 함수가

1. 누가 요청했는지 확인한다 — 관리자(로그인 세션) 또는 LMS 지사·선생님(role 1·2, `x-lms-token`),
2. 데이터베이스에 "이 칸의 현재 파일"과 하루 한도(회원당 KST 하루 30회, 관리자 제한 없음)를 묻고
   (`teacher_resource_issue`),
3. **15초 뒤 만료되는** 다운로드 주소를 만들어 돌려준다(만료 시간은 서버에 고정 — 브라우저가 바꿀 수 없음).

원본은 이 저장소의 `supabase/functions/teacher-resource-download/index.ts` **한 파일**이다(외부 라이브러리 없음).
대시보드 편집기는 버전 관리를 하지 않으므로 **고칠 때는 항상 저장소 파일을 고친 뒤 다시 붙여넣는다.**

## 언제

`supabase/migration.sql`(교사 자료실 블록 포함)을 운영에서 실행한 **뒤**. 함수가 부르는 `teacher_resource_issue`와
`teacher_resource_downloads` 표가 그 SQL에 들어 있다.

## 배포 (사용자, 대시보드에서 약 5분)

화면의 버튼 이름은 Supabase 대시보드 버전에 따라 조금 다를 수 있다.

| 단계 | 할 일                                                                                                                              |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Supabase 대시보드 → 이 프로젝트 → 왼쪽 메뉴 **Edge Functions**                                                                     |
| 2    | **Deploy a new function**(새 함수 배포) → **Via Editor**(편집기에서 만들기)                                                        |
| 3    | 함수 이름: **`teacher-resource-download`** — 한 글자라도 다르면 사이트가 함수를 찾지 못한다                                        |
| 4    | 편집기에 들어 있는 예시 코드를 **전부 지우고**, `supabase/functions/teacher-resource-download/index.ts` 내용 **전체**를 붙여넣는다 |
| 5    | **Deploy**(배포) 누르기 → 몇 초 뒤 함수 목록에 `teacher-resource-download`가 보이면 끝                                             |
| 6    | 함수 상세의 설정에서 **JWT 검증(Verify JWT / Enforce JWT verification)은 켜진 상태 그대로** 둔다(기본값)                           |

- **비밀 값은 아무것도 넣지 않는다.** `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`는 Supabase가 모든
  Edge Function에 자동으로 넣어 준다. service role 키를 Secrets 화면·코드·문서·채팅에 옮기지 않는다.
- JWT 검증을 켜 두면 사이트의 공개 키(anon)나 관리자 로그인 토큰이 없는 요청은 함수에 닿기 전에 막힌다. 나중에 Supabase API
  키를 새 방식(publishable/secret)으로 바꾼 뒤 다운로드가 모두 401로만 실패하면 이 설정을 끄면 된다 — 함수가 스스로 권한을
  판정하므로 꺼도 권한 없는 사람은 받지 못한다.

## 배포 후 확인

| 확인                       | 방법                                                                                                                                                                                                                  | 기대                                                            |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1. 함수가 살아 있다        | (작업자, PM 승인 시) 사전 요청 1회: `curl -i -X OPTIONS https://<프로젝트>.supabase.co/functions/v1/teacher-resource-download -H "Origin: https://www.cambridgereading.com" -H "Access-Control-Request-Method: POST"` | `204`, `Access-Control-Allow-Headers`에 `x-lms-token`           |
| 2. 선생님이 받을 수 있다   | 관리자로 작은 PDF 1개 업로드(배너 탭) → 선생님 테스트 계정으로 로그인 → 그 레벨 '교사 자료실' → 버튼                                                                                                                  | 같은 탭에서 파일이 저장되고, 이름이 올린 파일 이름(한글) 그대로 |
| 3. 학생·비로그인은 못 본다 | 학생 계정·로그아웃 상태로 월 선택 페이지                                                                                                                                                                              | '교사 자료실' 버튼 없음                                         |
| 4. 함수 기록               | 대시보드 → Edge Functions → `teacher-resource-download` → Logs / Invocations                                                                                                                                          | 2번 확인 때 200. 오류가 보이면 그 문구를 작업자에게             |

**문제 해결:** 다운로드를 누르면 브라우저 콘솔에 CORS 오류가 나고 함수 Logs에 사전 요청(OPTIONS)이 401로 찍히면, JWT 검증이
사전 요청까지 막고 있는 것이다 → 6단계의 JWT 검증을 끄고 다시 확인한다(함수가 스스로 권한을 판정하므로 안전하다).

로컬에서 미리 확인하려면 `npm.cmd run dev` → 브라우저 콘솔에 `craDevLive(true)` → 새로고침(로컬 주소
`http://127.0.0.1:5173`도 함수의 허용 출처에 들어 있다). 확인이 끝나면 `craDevLive(false)`.

## 하루 한도와 오류 화면

| 함수 응답 | 언제                                   | 선생님 화면 문구                                                 |
| --------- | -------------------------------------- | ---------------------------------------------------------------- |
| 200       | 정상                                   | (파일 저장)                                                      |
| 401       | 로그인 안 됨·학생·정지·로그아웃된 세션 | 다시 로그인해 주세요.                                            |
| 404       | 그 칸에 파일이 없음                    | 아직 준비 중이에요.                                              |
| 429       | 오늘(KST) 30회를 다 씀                 | 오늘 다운로드 횟수를 모두 사용했습니다. 내일 다시 시도해 주세요. |
| 그 외     | 네트워크·함수 미배포·Storage 오류      | 내려받지 못했어요. 잠시 후 다시 시도해 주세요.                   |

- 횟수는 **주소를 발급할 때** 센다(성공한 발급만). 기록은 `teacher_resource_downloads` 표에 남고 30일 지난 행은 함수가
  다음 발급 때 지운다. 표는 아무도 직접 읽거나 쓸 수 없다(함수 전용).
- 허용 출처(사이트 주소)를 바꿔야 하면 `index.ts`의 `ALLOWED_ORIGINS`를 고치고 다시 배포한다.
- 자동 테스트: `tests/teacher-resource-download.spec.js`(함수 로직, 가짜 fetch), `tests/teacher-resources-sql.spec.js`(DB).
